# What didn't work (and what we learned)

Everything we tried and replaced, dropped or had to fix, in one place. Failures are part of the evidence the judges ask for ("measured failures", "be honest about what's missing").
**Evidence levels:** 📊 reproducible from a script/report in the repo · 📝 measured in an ad-hoc run (script not saved; numbers recorded here and in the decision log) · 🔎 observed (logs, screenshots, commit history).

## Modeling

| # | What we tried | Result | What replaced it / lesson | Evidence |
|---|---|---|---|---|
| M1 | Using the organizer transcripts to learn intents | 171K transcripts have 42 distinct customer texts; every label is "consulta_general" | Wrote our own labeled ES/PT phrase set. Check the data can teach the task before choosing the method | 📊 reports/data_quality.md, data-issues B1–B2 |
| M2 | v0: e5-small + softmax, 7 families per label | 64% CV accuracy vs 79% for keyword rules; errors grouped by **topic**, not intent | More varied scenarios (+70 training families, hard negatives) → 75.5%. **Data variety beat model changes** | 📝 first CV run; 📊 current reports/embedding_comparison.md |
| M3 | k-nearest-neighbours on embeddings (k = 1, 3, 5, 9) | 49–53% CV accuracy | Dropped: worse than softmax regression with few examples per intent | 📝 intent-model.md D7 |
| M4 | Concatenating two embedding models (e5 + paraphrase-MiniLM) | 65–66% CV (+2 points) | Dropped: small gain for double the cost | 📝 D7 |
| M5 | Embeddings + character TF-IDF features | 58–60% CV (worse) | Dropped | 📝 D7 |
| M6 | Embeddings + keyword-rule outputs as features | 79–81% CV | **Rejected on principle:** the keywords encode the author's knowledge of held-out phrases, contaminating the comparison with the baseline | 📝 D9 |
| M7 | paraphrase-multilingual-MiniLM (expected to capture intent better) | 69.7% CV, below e5-small (75.5%) | Kept e5-small for v1. Our intuition was wrong; measure instead | 📊 embedding_comparison.md |
| M8 | distiluse-base-multilingual | 74.8% CV | Not better than e5-small | 📊 |
| M9 | LaBSE | 79.9% CV (+4.3, significant) | **Too big for Vercel** (472 MB vs 250 MB limit). Kept as a stretch goal (own server) | 📊 D6 |
| M10 | Amazon Titan Text Embeddings V2 (1024 and 512 dims) | 80.1% / 78.5% CV | Beaten by Cohere (84.6%); also 0.5–1 s per call and a 60/min quota | 📊 D15 |
| M11 | Char TF-IDF + softmax as a second baseline | 76.2% test, asks on 61% of clear messages | Kept only as a reference row | 📊 reports/intent_eval_*.md |
| M12 | v1 (e5-small) as the live model | 85.7% test | Replaced by v2 (Cohere, 91.7%); **kept as the in-app fallback** | 📊 |
| M14 | Banking77 (13K English banking queries) as extra training data (Miguel, 2026-09-30) | Accuracy unchanged (84.6% → 83.2–84.8%, McNemar p ≥ 0.13); more confident but more wrong actions (2.1% → 3.0–3.7%) and fewer questions on ambiguous messages | Rejected by the rule committed before the run; v2 stays. **Lesson:** more data can buy confidence without buying correctness; judge on wrong actions, not accuracy or coverage | 📊 reports/banking77_experiment.md, intent-model.md D17 |
| M13 | Near-duplicate threshold 0.92 (calibrated on translations) | Over-flags short phrases that share one word (109 flags, 2 real near-copies) | Kept, with manual review; documented that cosine similarity alone overstates leakage for short texts | 📊 reports/split_leakage.md |

## Evaluation process

| # | What went wrong | Impact | Fix / lesson | Evidence |
|---|---|---|---|---|
| E1 | v1 test runs 1–2 crashed while formatting the report (sort on a dropped column) | Metrics were computed and logged before the crash; no results displayed | Fixed the sort; all runs kept in the log | 📊 reports/test_runs.jsonl, D13 |
| E2 | v1 run 3: macro-F1 confidence interval scored labels missing from a resample as 0 | Lower bound shown as 0.54 instead of 0.73 | Compute F1 over labels present in each resample | 📊 D13 |
| E3 | The test set was reused for v2 | Each reuse weakens it a little | Decided on CV/validation, committed before the run, reported v1 and v2. A fresh human-written test set is still needed | 📊 D15 |
| E4 | Keyword baseline written before the new training data | It dropped to 60% on new vocabulary, which would have been an unfair comparison | Extended the rules from training data only (v2 rules) | 📊 D8 |
| E5 | Test-conversation expectations kept as prose in docs/test-conversations.md (Luis Pedro, 2026-10-01) | Porting TC-01…21 found 6 whose written expectations no longer match the code, mostly because later rules changed the behaviour (lookup, C15, PL-10): TC-07 expects PL-2 where the code lists both charges (PL-10), TC-03 ends "confirmed" where a person now takes it (PL-6) | Expectations live as code in `evals/cases/`, typed against the app's own values and checked by `npm test`; each records its basis and why it departs from the doc. **Lesson:** a prose test drifts silently; one that runs fails loudly | 📊 evals/cases/tc.ts notes |
| E6 | Step-17 scenarios quoted invented charges (Luis Pedro, 2026-10-01) | None of the 11 amounts belonged to a customer with a login (most existed for nobody), so every conversation would have ended in "not found" (PL-1) and tested one path | Charges swapped to the agreed customers (contracts.md K5), every edit recorded; `npm test` checks each expected charge belongs to the case's login. **Lesson:** check test data against the data before writing expectations | 📊 evals/cases/step17.ts, cases.test.ts |
| E7 | The stand-in lookup answered for customers it has no data for (Luis Pedro, 2026-10-01) | Without `SUPABASE_LOOKUP_DB_URL` the app silently used the stand-in; four persona cases found nothing and were graded as failures of the system | The runner records the lookup source per turn and marks such runs **invalid**, excluded from every number. **Lesson:** a harness must check its environment, not only the outcome | 📊 evals/run.ts, reports/eval_local-fallback.md |
| E8 | Local runs used the fallback model without saying so (Luis Pedro, 2026-10-01) | No `bedrock` profile on the laptop: every turn waited ~2 s for Cohere to fail, then used e5-small. Results and latency described degraded mode | Each turn records the model that answered; the report states the model mix and flags latency inflated by failed attempts. **Lesson:** record what actually served each answer, not what should have | 📊 reports/eval_local-fallback.md |
| E9 | 111 unit tests passed while two high-severity defects were live (Luis Pedro, 2026-10-01) | The harness found EF-1 (three matches + a merchant hand the customer off before the date is asked) and the break-it suite EF-4 (a PIN before its label isn't masked). No unit test combined those inputs | Both reported with model-free reproductions (docs/evaluation-findings.md). **Lesson** (as P17): unit tests check the cases we imagine; conversations against the running system find the ones we didn't | 📊 docs/evaluation-findings.md |
| E10 | Injection probes run on the fallback model (Luis Pedro, 2026-10-01) | PI-4 and PI-5 lowered e5-small's confidence, so the assistant asked a clarifying question and the probes never reached what they test (impersonation, a numeric timing promise) | Reported as safe but inconclusive; to re-run on Cohere. **Lesson:** an attack is only tested if the system reaches the step it targets | 📊 reports/eval_local-fallback.md |

## Production and infrastructure

| # | Problem | Cause | Fix / lesson | Evidence |
|---|---|---|---|---|
| P1 | Every production request returned 500 | onnxruntime-node needs its CommonJS files and native binary, which Vercel's file tracer didn't include | Explicit `outputFileTracingIncludes` (Linux x64 only) | 🔎 commit b770217, runtime logs |
| P2 | **The fallback crashing took down the primary path too** | The fallback module was imported at the top of the route | Lazy import; a broken fallback now only affects fallback traffic | 🔎 b770217 |
| P3 | First request after a deploy timed out, then the retry succeeded | **My first diagnosis (credentials) was incomplete.** The real main cause: loading the 118 MB fallback model at boot starved the first Bedrock call of CPU | Warm the fallback with `after()` (post-response); credentials get their own budget | 🔎 45d9389 (partial fix), f2f97cd (real fix), logs |
| P4 | Fallback confidences differ slightly from training (≤ 0.03) | Training embedded phrases in one batch; the 8-bit model calibrates per batch | Documented; embed one at a time before the next retrain | 🔎 parity check (28/28 labels matched) |
| P5 | Function over Vercel's 250 MB limit (287 MB runtime for every OS) | Package ships Mac/Windows/Linux binaries | Exclude non-Linux binaries (~204 MB total) | 🔎 next.config.ts |
| P6 | Build/type errors from `"name 2.ts"` files | The repo is on an iCloud-synced Desktop | tsconfig ignores the pattern; moving the repo recommended | 🔎 |
| P7 | No conversation memory: answers to clarifying questions misread, details re-asked | Phase 1 handles each message in isolation (known scope limit) | Fixed by steps 9 + 11 (conversation.md) | 🔎 docs/test-conversations.md |
| P8 | A refund demand overwrote the disputed amount ("devolviste 5000" replaced 120) (Miguel, 2026-09-29) | Details were merged on every turn, whatever the topic | Only dispute turns contribute details; unit test added. **Lesson:** "grounded in the text" isn't enough; the number must also be *about the charge* | 🔎 conversation.md C10, dialogue.test.ts |
| P9 | Using the intent model to read "review or agent?" answers (Miguel, 2026-09-29) | "revisen el cargo" scored `human_agent` 31%, dispute intents < 10%: trained on opening messages, not menu choices | Code reads menu choices with keywords, like yes/no. **Lesson:** a classifier answers the question it was trained on | 🔎 conversation.md C10 |
| P11 | Haiku overstated actions (Miguel, 2026-09-30) | "Tu disputa… **ha sido enviada**" before any record existed; "¡**Enseguida** te atenderá!" for a hand-off | Instructions now require future tense and forbid timing promises (reply-v3); verified live. **Lesson:** code can check numbers but not tense; step 13 makes "registered" true by verifying the record | 🔎 docs/policy.md |
| P12 | An amount limit ($500) proposed without evidence, and `compensation_granted` first read as a boolean (Miguel, 2026-09-30) | Caught in review by Miguel; measured: amounts are uniform, so the limit would flag almost nothing; compensation is an amount (6.9% of complaints) | Rule dropped; data issues E7–E8. **Lesson:** measure before proposing a threshold, and check a column's type before summarizing it | 📊 reports/fraud_threshold.md, docs/policy.md |
| P20 | A date silently dropped became a four-turn loop (Miguel, 2026-10-02) | "fue el 10 de octubre" was future (Haiku picked 2026) or past the 180-day window (2025); C3 dropped it without a word, the dialogue asked again, and Haiku echoed the date as if accepted. Nothing capped re-asks | Year-less future dates roll back a year; unusable dates are reported (too old → a person, PL-11; future → said); re-asks capped at two (C17). The 180-day limit itself had no recorded reason and was narrower than the 12 months of data: stated dates now reach 365 days. **Lesson:** every validation that drops input needs a visible outcome for the customer, every question needs a limit, and every cutoff needs a written reason (an unexplained 180 outlived the data it was meant to fit) | 🔎 conversation.md C17 |
| P19 | A bug that appears 1 run in 9 (Miguel, 2026-09-30) | Haiku sometimes read "debería ser de 250" as the charged amount, overwriting 350; the lookup found nothing and the case went to a person. 8 other runs were fine, locally and on the preview | Code guard C16; the smoke sweep gained `REPEAT=n`. **Lesson:** one passing run of a model-backed flow proves little; repeat the key conversations, and read the trace of the failing run: `detailsKnown` without `expectedAmount` pointed straight at it | 🔎 conversation.md C16 |
| P18 | The same bug class three times in one feature: a reply to our question read as a new topic (Miguel, 2026-09-30) | "sí" (P17), then "Cable TV" (out_of_scope 74%) and "el más reciente" (balance_check 81%) each dropped the conversation | C12b/c: when we asked a question, a reply that answers it is an answer, whatever the model says. **Lesson:** the intent model classifies opening messages; mid-conversation, "what did we just ask?" matters more than "what does this sentence look like?". Each case was found only by running the live model | 🔎 conversation.md C12b/c |
| P17 | A lone "sí" reset the conversation (Miguel, 2026-09-30) | The intent model scores "sí" as out_of_scope at 71%, above the 70% act threshold; mid-dispute it was treated as a confident new topic | C12: bare acknowledgements stay in the conversation. **Found by a 10-minute automated sweep (58 turns ×2), not by the 74 unit tests** whose hand-set scores never put a "sí" above the threshold. **Lesson:** unit tests check rules against scores we imagine; sweeps against the live model find the scores it actually produces | 🔎 conversation.md C12, scripts/smoke_sweep.mjs |
| P16 | "Amount" defined as "what was charged" broke declined purchases (Miguel, 2026-09-30) | "Por que recusaram minha compra de 560…" → 560 extracted as the expected amount; the assistant asked for the amount again | extract-v3 defines amount as the transaction's amount whatever its status. **Lesson:** a field definition written for one flow (disputes) silently breaks the next flow that reuses it (status); rerun every flow's cases after extending one | 🔎 conversation.md C3 update |
| P15 | Prompt-only rule broken a third time: an invented offer (Miguel, 2026-09-30) | On declined charges Haiku added "podemos investigarlo juntos" every time, even when told not to offer anything | Code check R9 for explain-only replies; template used. **Lesson (third time: P11, P13):** assume the model will fill a silence with a helpful-sounding promise; either back it with code or block it with code | 🔎 docs/handoff.md R9 |
| P14 | A card number followed by a comma wasn't masked (Miguel, 2026-09-30) | The pattern refused any number followed by "," or "." (to leave "1.250,00" alone), so "…1111 1111, mi pin" slipped through to the models. The unit test had no punctuation after the number; **found by reading the preview's trace** (`masked: ["secret"]` without `card`) | Pattern now blocks only a separator followed by a digit; tests with trailing/leading punctuation. **Lesson:** check the trace of every live test, not just the reply | 🔎 docs/handoff.md H4 |
| P13 | Prompt-only rule broken again: timing promises (Miguel, 2026-09-30) | reply-v3 forbade "right away", yet Haiku wrote "em breve" and "ahora mismo" in step 14 tests | Code check R8 rejects the reply and uses the template; a test runs every template through it, which caught our own "en unos minutos". **Lesson:** a rule that matters needs a code check; the prompt only lowers how often the check fires | 🔎 docs/handoff.md R8 |
| P10 | **The chat's fallback model was never bundled in production** (Miguel, 2026-09-30) | `next.config.ts` traced the fallback files for `/api/classify` only; `/api/chat` logged `Cannot find module 'onnxruntime-node'` since Phase 1. The outage test used `/api/classify`, so it passed | Same tracing rules for every route in `FALLBACK_ROUTES`; outage test now run on `/api/chat` too. **Lesson:** test the fallback on the route customers use, and read production logs after every deploy | 🔎 runtime logs dpl_7t6L… (pre-merge) and dpl_BnKk… |
